## :dart: O guia para alavancar a sua carreira

> Terraform é a ferramenta de Infraestrutura como Código (IaC) mais usada do mercado: com um único arquivo declarativo em HCL você provisiona servidores, redes, bancos de dados e recursos inteiros na AWS, Azure, Google Cloud ou em centenas de outros provedores, de forma versionada e reproduzível. Este guia reúne roadmap, cursos, documentação oficial, livros, canais, ferramentas do ecossistema, projetos práticos e comunidades sobre Terraform, com prioridade para conteúdo gratuito e em português. Serve tanto para quem nunca usou IaC quanto para quem já programa infraestrutura e quer se preparar para a certificação Terraform Associate ou aprofundar em módulos, estado remoto e automação. Todo link foi verificado na data da última revisão — guarde nos favoritos e volte sempre que precisar de uma trilha confiável.

> A proposta deste guia é dar uma ideia sobre o atual panorama e guiá-lo se você estiver confuso sobre qual será o seu próximo aprendizado, sem influenciar você a seguir os 'hypes' e 'trends' do momento. ## 🗺️ Roadmap
- [roadmap.sh — Terraform](https://roadmap.sh/terraform) — Guia passo a passo da comunidade sobre o que estudar em Terraform e em que ordem, com IA tutora integrada.
- [Introduction to Terraform (oficial, HashiCorp)](https://developer.hashicorp.com/terraform/intro) — Página oficial de introdução: o que é Terraform, por que usar e como ele se compara a outras ferramentas de IaC.
- [Terraform Associate (004) — trilha de certificação (HashiCorp)](https://developer.hashicorp.com/terraform/tutorials/certification-004) — Trilha oficial de estudo para a certificação, que funciona como um roadmap completo do básico ao avançado.
- [awesome-tf](https://github.com/shuaibiyy/awesome-tf) — Lista curada com centenas de recursos sobre Terraform e OpenTofu: livros, ferramentas, providers, módulos e vídeos, organizados por tema.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de IaC** — o que é Infraestrutura como Código, por que declarativo é melhor que scripts imperativos, o que o Terraform resolve.
2. **Instalação e primeiro `apply`** — instalar o CLI, configurar um provider (ex.: AWS) e criar seu primeiro recurso.
3. **Linguagem HCL** — blocos `resource`, `provider`, `variable`, `output`, `data source`, expressões e funções.
4. **Estado (state)** — o que é o `terraform.tfstate`, por que não versionar no Git e como usar backend remoto (S3, HCP Terraform).
5. **Módulos** — organizar código reutilizável, versionar módulos e publicá-los no Registry.
6. **Workflow em equipe** — `plan`/`apply` em pull request, locking de estado, workspaces e ambientes (dev/staging/prod).
7. **Qualidade e segurança** — lint (TFLint), análise estática de segurança (Checkov, tfsec) e estimativa de custo (Infracost) antes de aplicar.
8. **Avançado** — módulos dinâmicos, `import` de recursos existentes, CDK for Terraform, HCP Terraform/Terraform Enterprise e preparação para a certificação Associate.

## 🚀 Por onde começar
1. **Instale o Terraform** pelo [guia oficial de instalação](https://developer.hashicorp.com/terraform/install) (Homebrew, apt, Chocolatey ou binário direto) e confira com `terraform -version`.
2. **Instale a extensão oficial no VS Code** — [HashiCorp Terraform (Marketplace)](https://marketplace.visualstudio.com/items?itemName=hashicorp.terraform) — para ter autocomplete, formatação e validação do HCL.
3. **Siga o tutorial oficial do seu provedor:** [Get Started com AWS](https://developer.hashicorp.com/terraform/tutorials/aws-get-started), [Azure](https://developer.hashicorp.com/terraform/tutorials/azure-get-started), [Google Cloud](https://developer.hashicorp.com/terraform/tutorials/gcp-get-started) ou, para praticar sem conta em nuvem, [Docker](https://developer.hashicorp.com/terraform/tutorials/docker-get-started).
4. **Faça um curso gratuito em português:** o repositório-curso [Terraform na Prática](https://github.com/igordcsouza/terraform-na-pratica) ou o [Minicurso de Terraform (Iago Ferreira)](https://www.youtube.com/playlist?list=PLPqoPgWuohm5gnIJa7t-rMWUCYz9tI1xa) no YouTube.
5. **Leia a documentação da linguagem** — [Terraform Language Documentation](https://developer.hashicorp.com/terraform/language) cobre `resource`, `variable`, `output` e todo o HCL com exemplos.
6. **Entenda o estado antes de ir para produção** — [State (documentação oficial)](https://developer.hashicorp.com/terraform/language/state) explica por que o `.tfstate` nunca deve ir para o Git e como usar backend remoto.
7. **Pratique em um repositório real:** o [learn-terraform-modules (HashiCorp)](https://github.com/hashicorp-education/learn-terraform-modules) ensina a organizar código em módulos reutilizáveis.
8. **Valide seu código antes de aplicar:** rode [TFLint](https://github.com/terraform-linters/tflint) e [Checkov](https://github.com/bridgecrewio/checkov) nos seus primeiros arquivos `.tf` para pegar erros e problemas de segurança cedo.

Seu primeiro projeto em 60 segundos:

```bash
terraform -version                 # confirme a instalação
mkdir ola-terraform && cd ola-terraform
```

```hcl
# main.tf
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

resource "local_file" "ola" {
  filename = "${path.module}/ola.txt"
  content  = "Olá, Guia Dev Brasil!"
}
```

```bash
terraform init                     # baixa o provider e prepara o diretório
terraform plan                     # mostra o que será criado, sem aplicar nada
terraform apply                    # cria o arquivo de verdade (peça confirmação)
```

## 🛠️ Ferramentas
### Núcleo e workflow
- [Terraform CLI](https://developer.hashicorp.com/terraform/cli) — A ferramenta de linha de comando oficial: `init`, `plan`, `apply`, `state`, `workspace`.
- [Terraform Registry](https://registry.terraform.io/) — Repositório oficial de providers e módulos prontos para usar.
- [HCP Terraform](https://developer.hashicorp.com/terraform/cloud-docs) — Plataforma gerenciada da HashiCorp para rodar `plan`/`apply` remotamente, com Registry privado e políticas — plano gratuito disponível.
- [CDK for Terraform (CDKTF)](https://developer.hashicorp.com/terraform/cdktf) — Escreva a infraestrutura em linguagens de programação (TypeScript, Python, Go) em vez de HCL puro.
- [terraform-ls (Language Server)](https://github.com/hashicorp/terraform-ls) — Servidor de linguagem oficial que dá autocomplete e validação em qualquer editor compatível com LSP.
- [setup-terraform (GitHub Action)](https://github.com/hashicorp/setup-terraform) — Action oficial para instalar e rodar Terraform em pipelines de CI/CD no GitHub Actions.

### Providers oficiais
- [terraform-provider-aws](https://github.com/hashicorp/terraform-provider-aws) — Provider oficial para gerenciar recursos da AWS.
- [terraform-provider-azurerm](https://github.com/hashicorp/terraform-provider-azurerm) — Provider oficial para gerenciar recursos do Microsoft Azure.
- [terraform-provider-google](https://github.com/hashicorp/terraform-provider-google) — Provider oficial para gerenciar recursos do Google Cloud Platform.
- [terraform-provider-kubernetes](https://github.com/hashicorp/terraform-provider-kubernetes) — Provider oficial para gerenciar recursos dentro de um cluster Kubernetes.
- [terraform-provider-helm](https://github.com/hashicorp/terraform-provider-helm) — Provider oficial para instalar charts Helm via Terraform.

## 🤖 IA na prática
Terraform é declarativo (HCL, não uma linguagem de programação geral), o que muda como a IA ajuda: ela é ótima para gerar o "boilerplate" de um recurso, mas cada provider tem um schema próprio e versionado — nomes de argumentos mudam entre versões do `terraform-provider-aws`, por exemplo — e é exatamente aí que a IA mais erra.

**Para aprender**
- Peça para a IA **explicar a diferença entre um `terraform plan` e um `terraform apply`** com um exemplo do seu próprio arquivo `.tf`, e por que o `state` nunca deve ir para o Git.
- Cole um erro de `terraform apply` (ex.: `Error: Cycle` ou `Error: Invalid count argument`) e peça a causa raiz e a correção — mas sempre confira o resultado com `terraform plan` antes de aplicar.
- Peça para gerar um módulo simples (ex.: um bucket S3 com versionamento) e depois pergunte "quais argumentos desse resource você tem certeza que existem na versão atual do provider, e quais está assumindo?" — isso expõe alucinações antes de você rodar `apply`.
- Use a IA para transformar um `main.tf` único e desorganizado em módulos, e compare o resultado com o padrão oficial do [learn-terraform-modules](https://github.com/hashicorp-education/learn-terraform-modules).

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para escrever `variables.tf`/`outputs.tf` com descrições, gerar `.tfvars` de exemplo, escrever testes com Terratest e redigir o README de um módulo (depois valide com [terraform-docs](https://github.com/terraform-docs/terraform-docs)).
- O [terraform-mcp-server](https://github.com/hashicorp/terraform-mcp-server), oficial da HashiCorp e lançado em 2025, dá a agentes como Claude e Cursor acesso direto e atualizado ao Terraform Registry e à documentação de providers via Model Context Protocol — reduz bastante a alucinação de argumentos, porque o agente consulta o schema real em vez de "lembrar" de um treinamento desatualizado.
- Depois de **qualquer** sugestão aceita, rode `terraform validate`, [TFLint](https://github.com/terraform-linters/tflint) e [Checkov](https://github.com/bridgecrewio/checkov) — e sempre leia o `terraform plan` linha por linha antes do `apply`, principalmente se aparecer `-/+ destroy and re-create` num recurso com dados (banco, disco).

**Limites e boas práticas**
- IA **inventa argumentos e blocos** de providers com frequência, principalmente em recursos novos ou pouco documentados. Confirme sempre no [Terraform Registry](https://registry.terraform.io/) a versão exata do provider que você está usando.
- **Nunca cole o conteúdo de um `terraform.tfstate` ou de um `.tfvars` com segredos** (senhas, chaves de acesso) em uma ferramenta de IA — o state pode conter valores sensíveis em texto plano.
- Nunca deixe um agente de IA rodar `terraform apply` sozinho e sem revisão contra um ambiente de produção; trate o `plan` como o "diff" que você sempre revisa antes de aceitar uma mudança.
- Prefira sugestões que sigam os padrões do [HashiCorp Well-Architected Framework](https://developer.hashicorp.com/well-architected-framework) em vez de aceitar o primeiro código gerado sem questionar segurança e custo.
